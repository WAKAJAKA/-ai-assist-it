# Todo REST API Service

Сервис для управления задачами (Todo API), написанный на языке Go. Предоставляет программный интерфейс (API) для работы по протоколу HTTP и оснащен интерактивной веб-документацией Swagger (OpenAPI 2.0).

---

## Возможности сервиса

- **Просмотр задач**: получение общего списка или отдельной задачи по её идентификатору (ID).
- **Создание задач**: добавление новой записи с указанием заголовка, подробного описания и статуса готовности.
- **Обновление задач**: изменение отдельных полей существующей задачи.
- **Удаление задач**: исключение задачи из списка по её номеру.
- **Веб-документация**: просмотр описания всех маршрутов и отправка тестовых запросов через браузер.
- **Единый формат ответов**: все успешные данные возвращаются в объекте с отметкой успеха (`"success": true`) и полезной нагрузкой (`"data"`).

## Требования к окружению

Для сборки и запуска проекта потребуются:
1. **Go** — версии 1.21 или новее.
2. **Git** — система контроля версий.
3. **Утилита `swag`** — инструмент для автоматического создания документации Swagger из комментариев в коде.

### Проверка и установка Go

Проверьте наличие Go в командной строке:
```bash
go version
Если отображается версия (например, go version go1.21.x ...), переходите к следующему разделу.
Инструкция по установке, если Go отсутствует:
Windows:
Скачайте инсталлятор с официального сайта golang.org/dl и выполните установку.
Если команда go не распознаётся в терминале, добавьте путь к исполняемым файлам (по умолчанию C:\Program Files\Go\bin) в переменную окружения PATH:
Powershell
$env:Path += ";C:\Program Files\Go\bin"
[System.Environment]::SetEnvironmentVariable("Path", $env:Path, "User")
Перезапустите окно терминала.
macOS:
Bash
brew install go
Linux (Ubuntu/Debian):
Bash
sudo apt update && sudo apt install -y golang-go
Пошаговая установка и запуск
Шаг 1. Клонирование репозитория
Скачайте проект на локальный компьютер и перейдите в его каталог:
Bash
git clone https://github.com/WAKAJAKA/ai-assist-it.git
cd ai-assist-it
Шаг 2. Загрузка внешних пакетов
Загрузите необходимые библиотеки, указанные в файле go.mod:
Bash
go mod download
Шаг 3. Установка утилиты swag
Установите генератор документации:
Bash
go install github.com/swaggo/swag/cmd/swag@latest
Проверьте установку:
Bash
swag --version
Что делать, если возникает ошибка «команда не найдена»:
Убедитесь, что каталог установленных Go-программ включен в системную переменную PATH:
В Linux/macOS: добавьте в файл ~/.bashrc или ~/.zshrc строку export PATH=$PATH:$(go env GOPATH)/bin и обновите конфигурацию: source ~/.bashrc.
В Windows: добавьте %USERPROFILE%\go\bin в пользовательскую переменную окружения Path.
Шаг 4. Сборка файлов документации
Выполните генерацию спецификации Swagger:
Bash
swag init -g cmd/api/main.go -o docs
В каталоге docs/ будут сформированы файлы:
swagger.json и swagger.yaml — описание интерфейса API в стандартных форматах OpenAPI.
docs.go — связующий программный код для встроенного веб-сервера.
Примечание: эту команду необходимо повторять каждый раз при изменении комментариев к обработчикам запросов.
Шаг 5. Запуск сервера
Запустите приложение командой:
Bash
go run cmd/api/main.go
После успешного старта сервер принимает входящие подключения по адресу: http://localhost:8080.
Интерактивная веб-документация (Swagger UI)
После запуска проекта веб-интерфейс доступен в браузере:
Песочница и документация: http://localhost:8080/swagger/index.html
Позволяет выбирать любой метод, заполнять параметры формы и отправлять проверочные запросы к работающему сервису.
Спецификация в формате JSON: http://localhost:8080/swagger/doc.json
Примеры использования API (cURL)
Базовый адрес для всех запросов: http://localhost:8080
1. Получение списка всех задач
HTTP-метод: GET
Маршрут: /todos
Ожидаемый статус: 200 OK
Bash
curl -X GET http://localhost:8080/todos \
  -H "Accept: application/json"
Пример ответа сервера:
JSON
{
  "success": true,
  "data": [
    {
      "id": 1,
      "user_id": 101,
      "title": "Написать документацию",
      "description": "Оформить README.md и сгенерировать Swagger",
      "done": false,
      "created_at": "2026-11-09T10:00:00Z",
      "updated_at": "2026-11-09T10:00:00Z"
    }
  ]
}
2. Создание новой задачи
HTTP-метод: POST
Маршрут: /todos
Ожидаемый статус: 201 Created
Bash
curl -X POST http://localhost:8080/todos \
  -H "Content-Type: application/json" \
  -d '{
    "user_id": 101,
    "title": "Интегрировать Swagger",
    "description": "Добавить аннотации ко всем эндпоинтам",
    "done": false
  }'
Пример ответа сервера:

  "success": true,

    "updated_at": "2026-11-09T10:15:30.123456Z"
  }

Маршрут: /todos/1

Bash

Пример ответа сервера (заголовки HTTP):
Http

Date: Mon, 09 Nov 2026 10:25:00 GMT
Примеры сообщений при ошибках
Передан некорректный идентификатор (не число):
Запрос: GET /todos/abc
Статус: 400 Bad Request
Ответ: Неверный ID
Задача с указанным номером отсутствует:
Запрос: GET /todos/999
Статус: 404 Not Found
Ответ: Задача не найдена
Передан невалидный формат JSON:
Запрос: POST /todos с повреждённым телом
Статус: 400 Bad Request
Ответ: Невалидный запрос
